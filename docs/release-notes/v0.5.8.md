## FilePumper 0.5.8

Новая вкладка «Убрать метаданные» и команда `clean`, валидные пакеты Office после
накачки и два исправления окна.

### Что нового

- **Удаление метаданных.** Вкладка «Убрать метаданные» и команда `clean` убирают
  автора, даты, программы, комментарии и (по желанию) цветовые профили из
  готовых файлов: PNG (`tEXt`/`zTXt`/`iTXt`, `eXIf`, `tIME`, `iCCP`), JPEG (EXIF,
  XMP, IPTC, `COM`, APP2 ICC), GIF (комментарии, текстовые блоки, XMP), WebP
  (`EXIF`, `XMP`, `ICCP` с правкой флагов `VP8X`), SVG (`<metadata>`, `<title>`,
  `<desc>`, комментарии), `docx`/`xlsx`/`pptx` (`docProps/core.xml`, `app.xml`,
  `custom.xml`, превью) и PDF (`/Info`, `/Metadata`).
- **Содержимое не меняется.** Пиксели, текст документа и полезная нагрузка
  FilePumper (`ufPl`, `UFP1`, `<metadata id="ufpl…">`, `caBX`) остаются на месте,
  поэтому файл продолжает открываться.
- **Копия рядом с исходником.** Имя получает суффикс `_clean` (`--suffix` меняет
  его, `--out-dir` — папку), существующие файлы не перезаписываются: при
  совпадении добавляется `-2`, `-3`, …
- **Обзор «что найдено».** В окне список сразу показывает, какие блоки будут
  удалены и сколько они весят; в CLI то же делает `--dry-run`. Есть `--json`,
  `--report` (CSV/JSON) и `--profiles` — вместе с ICC-профилями и превью
  документов (по умолчанию профили сохраняются, чтобы не изменить цвета).

### Исправлено

- **Word больше не считает накачанный `docx` повреждённым.** Метод `office`
  дописывал в архив запись `word_media_cache.bin`, не объявлял её в
  `[Content_Types].xml` и требовал ZIP64 («версия распаковки» 4.5) — Word отвечал
  «обнаружено содержимое, которое не удалось прочитать» и предлагал
  восстановление с потерей данных. Теперь пакет пересобирается: тип содержимого
  заполнителя объявлен, остальные части копируются без распаковки и без ZIP64.
  То же для `xlsx` и `pptx`.
- **Точный размер для `office`.** В цель входят и служебные поля записи: раньше
  файл получался примерно на 1,3 КБ больше запрошенного размера.
- **Повторная накачка не плодит части.** Прежняя часть заполнения (включая
  `word_media_cache.bin` от старых версий) заменяется новой.
- **Пример имени в окне совпадает с выбранным файлом.** Раньше всегда
  показывалось `Пример: photo.png`; теперь пример строится по первому файлу
  списка, поэтому для `.docx` видно `…_19MB.docx`, а не `.png`.
- **«Показать в проводнике» действительно ведёт к файлу.** Проводник получал
  `/select,<путь>` без кавычек и обрезал путь на первом пробеле — открывались
  «Документы», файл не выделялся. Теперь путь передаётся в кавычках, каталог
  открывается как каталог, для удалённого файла — его папка, а для одного
  результата в окне «Готово» показан путь к файлу.

### Примеры

```powershell
# убрать автора, даты и комментарии из фото и документа
FilePumper-cli.exe clean .\photo.jpg .\report.docx --out-dir .\clean

# только посмотреть, что найдено, ничего не записывая
FilePumper-cli.exe clean .\photo.jpg --dry-run

# вместе с ICC-профилями и превью документов, свой суффикс
FilePumper-cli.exe clean .\scan.png --profiles --suffix -no-meta
```

### Что не менялось

Формат контейнера (версия 2), шифрование (Argon2id + ChaCha20-Poly1305),
команды `pump`/`generate`/`embed`/`extract`/`inspect`/`verify` и сохранённые
профили окна: файлы и настройки от 0.5.7 и раньше читаются этой версией без
изменений.

### Требования

- **Windows:** DirectX 12 или Vulkan для окна; если система ругается на
  отсутствующие DLL — Microsoft Visual C++ 2015-2022 x64.
- **Linux:** glibc ≥ 2.17; для окна нужны X11 или Wayland и драйвер Vulkan/Mesa;
  CLI-версии кроме `libc` ничего не требуется.

### Как собрано и проверено

- `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` и
  `cargo test` — 209 тестов. Новое покрыто отдельно: разбор метаданных по форматам
  (PNG, JPEG, GIF, WebP, SVG, Office, PDF), команда `clean` целиком и отсутствие
  метаданных у созданных программой картинок.
- Проверено на настоящих файлах: `docx`/`xlsx`/`pptx` (python-docx, openpyxl,
  python-pptx открывают, свойства пустые), PDF (рендерится после правки), JPEG
  (EXIF 4 тега → 0, пиксели совпадают), PNG, GIF, WebP, SVG.
- Сборка релиза — workflow `Release` по тегу `v0.5.8`: Windows
  (`cargo build --release --bins`) и Linux (`cargo zigbuild`, glibc 2.17);
  те же проверки повторяет workflow `CI` на Windows и Linux.

### Быстрый старт

```powershell
# окно: вкладка «Убрать метаданные» — добавьте файлы и нажмите кнопку
FilePumper.exe

# CLI: убрать метаданные из папки, оставив копии рядом
FilePumper-cli.exe clean --from-dir .\docs --suffix _clean
```

```bash
tar -xzf FilePumper-0.5.8-linux-x64.tar.gz
chmod +x linux/file-pumper linux/file-pumper-cli
./linux/file-pumper-cli clean ./photo.jpg --dry-run
```

Полное описание режимов, формата контейнера и всех команд — в [README.md](https://github.com/Xvicd/FilePumper/blob/main/README.md).
