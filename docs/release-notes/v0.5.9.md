## FilePumper 0.5.9

Дробный размер в имени файла больше не выглядит расширением, а количество
файлов в серии вводится руками — до 10 000 за запуск.

### Что изменилось

- **Размер в имени файла — через `_`.** `photo_12.3MB.png` стало
  `photo_12_3MB.png`, `seed_0.25MB.bin` — `seed_0_25MB.bin`. Точка в дробной
  части читалась как начало расширения, и Windows мог сбросить формат файла.
  В консоли, отчётах и подсказках размер по-прежнему показывается с точкой
  (`12.3 МБ`), меняется только имя результата.
- **Количество файлов вводится руками.** На вкладке «Создать файл» вместо
  счётчика с потолком 32 — текстовое поле: введите любое число от 1 до 10 000.
  `--count` в CLI принимает столько же (раньше молча обрезал до 64). Если
  ввести не число или выйти за границы, под полем появится подсказка, а
  генерация не начнётся.
- **Серия по-прежнему не перезаписывает файлы.** Занятое имя получает суффикс
  `-2`, `-3`, … — это важно при больших `--count`.

### Примеры

```powershell
# 12,3 МБ — имя photo_12_3MB.png (точка не попадает в имя)
FilePumper-cli.exe generate --size 12.3 --type png --name photo --out-dir .\made

# сто файлов по 10 КБ за один запуск (раньше --count молча обрезался до 64)
FilePumper-cli.exe generate --size 0.01 --type bin --name many --count 100 --out-dir .\made
```

В окне: вкладка «Создать файл» → поле «Файлов на размер» → введите число
руками. Рядом показывается «всего файлов: N» с учётом `--mix` и числа типов.

### Что не менялось

Формат контейнера (версия 2), шифрование (Argon2id + ChaCha20-Poly1305),
команды `pump`/`generate`/`embed`/`extract`/`inspect`/`verify`/`clean` и
сохранённые профили окна: файлы и настройки от 0.5.8 и раньше читаются этой
версией без изменений. Единственное отличие — новые имена результатов с
дробным размером; старые файлы с точкой в имени открываются как обычно.

### Требования

- **Windows:** DirectX 12 или Vulkan для окна; если система ругается на
  отсутствующие DLL — Microsoft Visual C++ 2015-2022 x64.
- **Linux:** glibc ≥ 2.17; для окна нужны X11 или Wayland и драйвер Vulkan/Mesa;
  CLI-версии кроме `libc` ничего не требуется.

### Как собрано и проверено

- `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` и
  `cargo test` — 210 тестов.
- Добавлены проверки: имя с дробным размером (`photo_12_3MB.png`,
  `seed_0_25MB.bin`), подпись размера для консоли не изменилась, а тест
  разброса (`--vary`) сравнивает подпись с фактическим размером уже с учётом
  `_`.
- Проверено вручную: `generate --size 12.3` даёт `photo_12_3MB.png` ровно на
  12 897 484 байта; `--count 100` создаёт сто файлов; поле ввода в окне
  принимает число руками.
- Сборка релиза — workflow `Release` по тегу `v0.5.9`: Windows
  (`cargo build --release --bins`) и Linux (`cargo zigbuild`, glibc 2.17);
  те же проверки повторяет workflow `CI` на Windows и Linux.

### Быстрый старт

```powershell
# окно: «Создать файл» → введите количество файлов руками
FilePumper.exe

# CLI: серия из 500 файлов по 4 МБ
FilePumper-cli.exe generate --size 4 --type png --count 500 --out-dir .\series
```

```bash
tar -xzf FilePumper-0.5.9-linux-x64.tar.gz
chmod +x linux/file-pumper linux/file-pumper-cli
./linux/file-pumper-cli generate --size 12.3 --type png --name photo --out-dir ./made
```

Полное описание режимов, формата контейнера и всех команд — в [README.md](https://github.com/Xvicd/FilePumper/blob/main/README.md).
