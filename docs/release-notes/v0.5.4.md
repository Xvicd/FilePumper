## FilePumper 0.5.4

Групповая работа с нагрузкой (обзор, извлечение списком, пары «что во что») и
исправленное расширение у извлечённого файла.

### Что исправлено

- **Извлечённый файл больше не теряет расширение.** Диалог сохранения открывался
  без фильтра по типу файла, поэтому Windows мог вернуть имя без расширения — и
  `song.mp3` становился файлом, который нечем открыть. Теперь диалог получает
  фильтр по расширению нагрузки, а извлечение само подставляет расширение из
  имени внутри контейнера, если в выбранном имени его нет: `--output song` даёт
  `song.mp3`.
- **Обычный файл в пакете больше не считается ошибкой.** `extract a.png b.png`,
  где в `b.png` ничего нет, печатает «Нагрузки нет: b.png — обычный файл», итог
  «извлечено 1 из 2, без нагрузки 1» и завершается с кодом 0. Код 1 остаётся для
  настоящих ошибок: файл не читается, пароль не подошёл, контейнер повреждён.
  Для одного носителя без нагрузки ошибка сохраняется.

### Что нового

- **«Проверить все»** — обзор сразу нескольких файлов: по строке на файл
  (`photo.png — song.mp3 (48.8 КБ, пароль)`, `plain.png — ничего не спрятано`) и
  итог «с нагрузкой 2 из 3». В CLI то же делает `inspect` с несколькими путями и
  блоком «Что можно извлечь» в конце.
- **«Извлечь всё в папку…»** — групповое извлечение: одиночные файлы сохраняются
  под именем из контейнера вместе с расширением, бандлы распаковываются (один
  бандл — прямо в папку, несколько — каждый в подпапку по имени носителя). В CLI
  это `extract` с несколькими носителями и `--out-dir`.
- **Пары «что во что»** — блок в окне: «Сопоставить по порядку» строит пары
  «носитель ← нагрузка», у каждой пары своё поле пароля, кнопка «Спрятать по
  парам» пишет файл за файлом и показывает состояние каждой пары. В CLI —
  `embed --pair` и повторяемый `--pair-password ПАРОЛЬ`.
- **Своё поле пароля для проверки и извлечения** в окне — чтобы не перебивать
  пароль встраивания. Паролей можно указать несколько через запятую, в CLI —
  повторив `--password`: они проверяются по порядку, поэтому пачка файлов с
  разными паролями проверяется и извлекается одной командой.

### Что изменилось в поведении

- Перетаскивание файлов в окно складывает их в список носителей (и в пакет): так
  перетащенные файлы сразу можно проверить и извлечь. Что спрятать — выбирается
  отдельно.
- Кнопка «Проверить и извлечь» стала «Один файл: сохранить как…» и доступна,
  когда выбран ровно один носитель.

### Что не менялось

Формат контейнера (версия 2), шифрование (Argon2id + ChaCha20-Poly1305), имена
результатов накачки и размеры файлов. `embed` без `--pair` работает как раньше:
все нагрузки попадают в каждый носитель (несколько — бандлом). Файлы, созданные
0.5.3 и раньше, читаются этой версией без изменений.

### Требования

- **Windows:** DirectX 12 или Vulkan для окна; если система ругается на отсутствующие DLL — Microsoft Visual C++ 2015-2022 x64.
- **Linux:** glibc ≥ 2.17; для окна нужны X11 или Wayland и драйвер Vulkan/Mesa; CLI-версии кроме `libc` ничего не требуется.

### Как собрано и проверено

- `cargo test --all-targets` — 157 тестов (89 unit, 6 пакетный CLI, 13 возможностей
  CLI, 11 генерации, 8 разброса, 10 режимов имён, 7 групп и пар, 8 устойчивость,
  5 сквозных), `cargo clippy --all-targets -- -D warnings` и `cargo fmt --check`
  без замечаний.
- Windows (собрано локально, `cargo build --release --bins`): `--version` →
  `FilePumper 0.5.4`; `embed --pair --pair-password` раскладывает нагрузки по
  носителям, `inspect` с обычным файлом в списке печатает итог и не падает,
  `extract` с обычным файлом в списке возвращает код 0, извлечённый `song.mp3`
  сохраняется с расширением и совпадает по SHA-256 с исходником.
- Linux (сборка CI, `zigbuild` glibc 2.17; проверено в WSL Kali): `file-pumper-cli
  --version` → `FilePumper 0.5.4`, `ldd` — только
  `libc`/`libm`/`libpthread`/`libdl`.

### Быстрый старт (Linux)

```bash
tar -xzf FilePumper-0.5.4-linux-x64.tar.gz
chmod +x linux/file-pumper linux/file-pumper-cli
./linux/file-pumper-cli inspect ./photos/*.png ./docs/note.pdf --password пароль
./linux/file-pumper-cli embed ./photos/*.png --payload ./secret.zip --pair --out-dir ./out
```

Полное описание режимов, формата контейнера и всех команд — в [README.md](https://github.com/Xvicd/FilePumper/blob/main/README.md).
