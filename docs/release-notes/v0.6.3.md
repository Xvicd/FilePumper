## FilePumper 0.6.3

Нагрузка теперь умеет жить внутри документов: отдельной частью пакета в
DOCX/XLSX/PPTX и неиспользуемым потоком в PDF. Добавлены ключ-файл, схема
Шамира, проверка переживания перекодирования и «умная» накачка Office.

### Что нового

- **Нагрузка внутри DOCX/XLSX/PPTX.** Отдельная часть `filepumper/payload.bin`,
  объявленная в `[Content_Types].xml`: Word, Excel и PowerPoint открывают файл
  как обычный документ, а `extract`/`verify`/`inspect` находят нагрузку.
- **Нагрузка внутри PDF.** Неиспользуемый поток-объект перед `%%EOF`: xref и
  `startxref` не меняются, документ открывается и печатается как прежде.
- **`extract --only ИМЯ`** — из бандла извлекается только одна запись (без учёта
  регистра); если имя не совпало, файл не пишется и команда сообщает об ошибке.
- **PDF глубже.** Кроме `/Info` и `/Metadata` вычищаются `/OpenAction`, `/AA`,
  `/Names`, `/AcroForm` и `/Annots` — правки одинаковой длины, структура файла
  не страдает.
- **DOCX глубже.** Удаляются служебные идентификаторы правок `w:rsid…`; текст и
  форматирование не меняются.
- **Метаданные MP4/MOV.** Удаляются боксы `udta` (теги, обложки), размеры
  контейнеров пересчитываются.
- **Ключ-файл (`--keyfile`).** Содержимое файла подмешивается к паролю при
  выводе ключа Argon2id: без того же ключ-файла нагрузка не расшифруется. Работает
  в `embed`, `extract`, `inspect`, `verify`, `generate --payload` и в окне (поле
  «Ключ-файл»).
- **Схема Шамира.** `share <файл> --parts N --threshold K` делит файл на части,
  `join` собирает его из любых K частей; части — обычные файлы `.share1`,
  `.share2`, …; меньше K частей не дают ничего. В окне — группа «5. Разделить
  секрет на части».
- **Проверка перекодирования.** `inspect --recompress` пересобирает картинку тем
  же форматом и сообщает, уцелеет ли нагрузка; в окне — кнопка «Проверить
  перекодирование».
- **Умная накачка Office.** Заполнение уходит в рост существующей медиа-части
  (`word/media/*.png|jpg`), а не в отдельную часть-заполнитель: документ выглядит
  как обычный файл с картинкой. Если медиа-частей нет — прежняя часть-заполнитель.

### Примеры

```powershell
# нагрузка внутри Word и PDF
FilePumper-cli.exe embed .\report.docx .\doc.pdf --payload .\secret.zip --out-dir .\out
FilePumper-cli.exe extract .\out\report_with_payload.docx --out-dir .\restored

# ключ-файл вместе с паролем
FilePumper-cli.exe embed .\photo.png --payload .\secret.zip --password pw --keyfile .\key.bin --out-dir .\out

# разделить на 5 частей, собрать из любых 3
FilePumper-cli.exe share .\secret.zip --parts 5 --threshold 3 --out-dir .\parts
FilePumper-cli.exe join .\parts\secret.zip.share1 .\parts\secret.zip.share3 .\parts\secret.zip.share5 --output .\secret.zip

# проверить, переживёт ли нагрузка перекодирование
FilePumper-cli.exe inspect .\out\photo_with_payload.png --recompress
```

### Ограничения

- OGG-комментарии не поддерживаются (по решению заказчика — не нужны).
- Нагрузка внутри DOCX/PDF не шифруется отдельно от контейнера: те же
  `--password` и `--keyfile`, что и у остальных носителей.

### Совместимость

Формат контейнера (версия 2), команды `pump`/`generate`/`embed`/`extract`/
`inspect`/`verify`/`clean` и сохранённые профили не менялись: файлы и настройки
от 0.6.2 и раньше читаются этой версией без изменений. Ключ-файл — новое
необязательное поле: без него поведение прежнее.

### Требования

- **Windows:** DirectX 12 или Vulkan для окна; если система ругается на
  отсутствующие DLL — Microsoft Visual C++ 2015-2022 x64.
- **Linux:** glibc ≥ 2.17; для окна нужны X11 или Wayland и драйвер Vulkan/Mesa;
  CLI-версии кроме `libc` ничего не требуется.

### Как собрано и проверено

- `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings` и
  `cargo test` — 256 тестов.
- Проверено вручную: DOCX с нагрузкой открывается python-docx (часть
  `filepumper/payload.bin` на месте), PDF с нагрузкой рендерится LibreOffice,
  `verify` — OK, `extract` возвращает файл байт-в-байт; умная накачка docx с
  картинкой: 182 КБ → ровно 2 МиБ без частей-заполнителей, `word/media/image1.png`
  вырос, python-docx открывает; ключ-файл: без него и с другим ключом — ошибка,
  с ним — OK; Шамир: любые 3 из 5 восстанавливают файл, 2 из 5 — ошибка.
- Сборка релиза — workflow `Release` по тегу `v0.6.3`: Windows
  (`cargo build --release --bins`) и Linux (`cargo zigbuild`, glibc 2.17);
  те же проверки повторяет workflow `CI` на Windows и Linux.

### Быстрый старт

```powershell
# окно: «Спрятать / извлечь» → выбрать носители и нагрузки → «Спрятать файл»
FilePumper.exe

# CLI: спрятать в Word и PDF, потом достать
FilePumper-cli.exe embed .\report.docx .\doc.pdf --payload .\secret.zip --out-dir .\out
FilePumper-cli.exe extract .\out\report_with_payload.docx --out-dir .\restored
```

```bash
tar -xzf FilePumper-0.6.3-linux-x64.tar.gz
chmod +x linux/file-pumper linux/file-pumper-cli
./linux/file-pumper-cli embed ./report.docx --payload ./secret.zip --out-dir ./out
```

Полное описание режимов, формата контейнера и всех команд — в [README.md](https://github.com/Xvicd/FilePumper/blob/main/README.md).
