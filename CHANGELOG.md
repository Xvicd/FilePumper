# Changelog

Все заметные изменения проекта. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning](https://semver.org/lang/ru/).

## [0.5.5] — 2026-11-09

Массовое создание файлов сразу нескольких типов: отметил форматы, задал
количество — и получил смешанную серию. Распределение на выбор: поровну на
каждый тип или случайно из отмеченных.

### Добавлено

- **Несколько типов файлов за один запуск.** На вкладке «Создать файл» вместо
  одного выпадающего списка — чекбоксы `.bin`, `.png`, `.gif`, `.jpg`, `.webp`
  и кнопки «Все типы» / «Только .bin»; в CLI — список в `--type`:
  `generate --type png,gif,bin` (или `--type all`). Каждый файл серии получает
  свой тип, поэтому в одной папке оказываются и картинки, и обычные файлы.
- **Распределение типов** (`batch::MixMode`): «поровну на каждый тип»
  (`--mix even`, по умолчанию) — по `--count` файлов каждого отмеченного типа;
  «случайно из выбранных» (`--mix random`) — всего `--count` файлов, а тип
  каждого выбирается случайно. В окне это поле «Распределение» рядом с числом
  файлов; при одном отмеченном типе оно скрыто.
- **Подсказка об итоге в окне**: «всего файлов: N» и примеры имён для каждого
  отмеченного типа — с учётом режима «Имена» и разброса.
- **`GeneratedKind::parse_list`** — разбор списка типов (`png,gif`, `all`,
  повторы отбрасываются, пустой список — ошибка).

### Изменено

- `batch::plan_generate` больше не принимает тип отдельным аргументом: типы и
  режим распределения лежат в `GenerateTargets` (поля `kinds` и `mix`). План
  по-прежнему плоский список `GenerateItem`, у каждого элемента своё `kind`.
- `--count` при нескольких типах считается по распределению:
  `--type png,gif --count 2` создаёт по два файла каждого типа, а
  `--mix random` — ровно `--count` файлов всего.
- `--dry-run` печатает все выбранные типы и распределение, а не один тип.

### Совместимость

- `generate --type png --count 3` работает как раньше: один тип, ровно три
  файла. Без `--type` создаётся `.bin`, как прежде.
- Формат контейнера, накачка, встраивание и извлечение не менялись; сохранённые
  настройки окна читаются — новые поля берут значения по умолчанию.

## [0.5.4] — 2026-11-08

Групповая работа с нагрузкой: пары «носитель ← файл» со своими паролями, обзор
нескольких файлов и извлечение всего найденного в одну папку. Плюс исправлено
исчезновение расширения у извлечённого файла.

### Исправлено

- **Извлечённый файл больше не теряет расширение.** Диалог сохранения открывался
  без фильтра по типу файла, поэтому Windows мог вернуть имя без расширения —
  и `song.mp3` превращался в файл, который нечем открыть. Теперь диалог получает
  фильтр по расширению нагрузки, а `payload::extract_to` дополнительно
  подставляет расширение из имени внутри контейнера, если в выбранном имени его
  нет (`payload::with_payload_extension`). Работает и для `--output song`, —
  результат будет `song.mp3`.
- **Обычный файл в пакете больше не считается ошибкой.** `extract a.png b.png`,
  где внутри `b.png` ничего нет, печатает «Нагрузки нет: b.png — обычный файл»,
  итог «извлечено 1 из 2, без нагрузки 1» и завершается с кодом 0. Код 1 остаётся
  только для реальных проблем: файл не читается, пароль не подошёл, контейнер
  повреждён. Для одного носителя без нагрузки ошибка сохраняется.

### Добавлено

- **Обзор нескольких файлов** (`payload::group::scan_many`, `ScanItem`): в окне —
  кнопка «Проверить все», которая печатает по строке на файл
  (`photo.png — song.mp3 (48.8 КБ, пароль)`, `plain.png — ничего не спрятано`) и
  итог «с нагрузкой 2 из 3»; в CLI — то же в `inspect` с блоком «Что можно
  извлечь» в конце отчёта.
- **Групповое извлечение** (`payload::group::extract_many`, `ExtractBatch`): в
  окне — «Извлечь всё в папку…», в CLI — `extract` с несколькими носителями и
  `--out-dir`. Одиночные файлы сохраняются под именем из контейнера вместе с
  расширением, бандлы распаковываются (в подпапку по имени носителя, если
  носителей несколько). Отчёт печатает строку на каждый файл.
- **Пары «что во что»** (`payload::group::EmbedPair`, `pair_by_order`): в окне —
  блок «Что во что», кнопка «Сопоставить по порядку» и список пар с отдельным
  паролем на пару, кнопка «Спрятать по парам»; в CLI — `embed --pair` с
  повторяемым `--pair-password ПАРОЛЬ`. Нагрузок меньше, чем носителей — они
  повторяются по кругу, больше — делятся поровну и попадают в носитель бандлом.
- **Свой пароль для проверки и извлечения** в окне: отдельное поле, чтобы не
  перебивать пароль встраивания. Паролей можно указать несколько через запятую —
  они проверяются по порядку; в CLI для этого `--password` повторяют. Так пачка
  файлов, спрятанных с разными паролями, проверяется и извлекается одной командой
  (`payload::group::probe`).

### Изменено

- Перетаскивание файлов в окно складывает их в список носителей (и в пакет), а не
  в «носитель + нагрузка»: так перетащенные файлы сразу можно проверить и
  извлечь, а что спрятать — выбирается отдельно.
- Кнопка «Проверить и извлечь» стала «Один файл: сохранить как…» и доступна,
  когда выбран ровно один носитель.

### Совместимость

- Формат контейнера не менялся: файлы, созданные 0.5.3 и раньше, читаются как
  прежде. `embed` без `--pair` работает как раньше (все нагрузки в каждый
  носитель), `extract`/`inspect` без новых флагов тоже.

### Инфраструктура

- Описание релиза теперь собирается автоматически из `docs/release-notes/<тег>.md`:
  workflow подставляет в `{{WIN_SHA}}` и `{{LINUX_SHA}}` реальные SHA-256
  залитых архивов (`gh release edit --notes-file`), поэтому хеши в описании
  всегда совпадают с файлами и ручной шаг `release_checksums.py --patch` больше
  не нужен (скрипт остался для проверки).

## [0.5.3] — 2026-11-08

Случайные имена на выбор: слова `green-apple-4821` или набор символов `k7fq2mzp`.

### Добавлено

- **Вид случайного имени** (`batch::RandomStyle`, `batch::RandomNames`): у режима
  «случайное» теперь два способа — «слова» (`green-apple-4821`: прилагательное,
  существительное и четырёхзначное число) и «набор символов» (`k7fq2mzp`: только
  выбранные символы заданной длины 3…48, по умолчанию 10).
- **Алфавит случайного имени настраивается.** В окне — поле «Символы» и готовые
  наборы `a-z`, `a-z0-9`, `0-9`, `hex`, `A-Za-z0-9`; в CLI — флаги
  `--random-style words|chars`, `--random-length N`, `--random-alphabet НАБОР`.
  Всё, что не годится для имени файла, отбрасывается (остаются латиница, цифры,
  «-» и «_»), окно предупреждает об этом, а CLI пустой алфавит считает ошибкой.
- **Кнопка «другой пример»** рядом с примером имени: показывает ещё один вариант
  случайного имени.

### Исправлено

- Пример имени в окне больше не «перебирает» варианты на каждом кадре: случайная
  основа для примера берётся по зерну (`batch::sample_result_name`,
  `batch::sample_generated_name`), поэтому пока настройки не меняли, пример стоит
  на месте и меняется только по кнопке «другой пример».
- `--names` и `--random-style` понимают слова в любом регистре, включая кириллицу:
  `--names Случайное`, `--random-style СИМВОЛЫ`.

### Совместимость

- `--names random` без новых флагов даёт те же имена, что и раньше
  (`quiet-river-4821.png`): формат файлов, размеры и поведение команд не менялись.
- Сохранённые настройки окна переносятся без потерь: новые поля берут значения по
  умолчанию.

## [0.5.2] — 2026-11-08

Точная подсказка о разбросе в окне.

### Исправлено

- Подсказка «в какой диапазон попадёт размер» в окне считалась от указанного
  размера и не учитывала режим размера. При режимах «не меньше» и «прибавить»
  база зависит от исходного файла, поэтому числа были неверными (например,
  «от 8,00 до 12,00 МБ» вместо «исходный размер + 8…12 МБ»). Теперь в этих
  режимах вместо диапазона печатается правило: «Разброс ±5MB применится к
  размеру, который получится после режима «прибавить»». Диапазон в мегабайтах
  показывается только для режима «точно», где он и считается от введённого
  размера.
- Предупреждение «разброс не меньше самого размера» тоже показывается только в
  режиме «точно»: в остальных режимах база больше указанного размера, и
  предупреждение было ложной тревогой.

### Совместимость

- Поведение команд, формат файлов и размеры не менялись: 0.5.2 исправляет
  только текст подсказки в интерфейсе, поэтому результаты 0.5.1 и 0.5.2
  неотличимы. Обновляться стоит ради понятного окна.

## [0.5.1] — 2026-11-08

Разброс размера «плюс-минус» и переработанное окно.

### Добавлено

- **Разброс размера** (`batch::SizeJitter`, `batch::JitterMode`): флаги
  `--vary <МБ>` и `--vary-mode plus|minus|both` в `pump` и `generate`. Вместо ровных
  400 МБ файл получает случайный размер в заданных пределах
  (`--size 400 --vary 5` → 395…405 МБ), направление выбирается: только плюс,
  только минус или в обе стороны (по умолчанию). Отклонение считается для каждого
  файла пакета отдельно, применяется после `--size-mode` и не опускает размер ниже
  одного байта. Точность сохраняется: файл записывается ровно того размера, который
  выпал, поэтому `--verify` проходит, а размер в имени (`photo_3.87MB.png`) —
  фактический. `--vary 0` выключает разброс; если разброс не меньше самого размера,
  печатается предупреждение.
- **В окне** — поля «Разброс» и «Направление» с подсказкой, в какой диапазон попадёт
  размер: «Каждый файл получит случайный размер от 395,00 до 405,00 МБ (плюс-минус 5MB)».
- Тесты: `tests/cli_jitter.rs` (8 тестов — диапазоны `plus`/`minus`/`both`, `--vary 0`,
  `--verify` на выпавшем размере, `--dry-run`, ошибки ввода, размер в имени) и
  unit-тесты `batch` (разбор направления, границы разброса, отсутствие нулевого
  файла, план накачки и план генерации с разбросом).

### Изменено

- **Окно переработано для понятности**: вместо длинной ленты из пяти пунктов —
  три вкладки («Накачать файлы», «Спрятать / извлечь», «Создать файл»), настройки
  собраны в группы с заголовками, на каждой вкладке одна крупная кнопка запуска,
  статус и прогресс с кнопкой «Отмена» закреплены внизу окна и видны всегда.
  Функциональность сохранена полностью: методы, режимы размера, имена результатов,
  папка результатов, носители и нагрузка, сжатие, копии, пароль, «второе дно»,
  прогресс, отмена, окно результата с «Показать в проводнике», предпросмотр
  извлечения, drag & drop, сохранение настроек. Дополнительно запоминаются режим
  имён, разброс и открытая вкладка.
- Имена результатов выбираются тремя радиокнопками (с размером / без размера /
  случайное) вместо переключателя с галочкой.
- В окне появилась кнопка «Добавить папку...»: папка добавляется вместе с
  подпапками (раньше папку можно было только перетащить).

### Совместимость

- Формат контейнера не менялся (версия 2): файлы 0.5.0 читаются этой версией, а
  файлы 0.5.1 без новых возможностей — версией 0.5.0.
- Новые флаги (`--vary`, `--vary-mode`) старым версиям неизвестны — они сообщат об
  ошибке в аргументах, но созданные файлы читают нормально.
- Старые сохранённые настройки окна читаются: недостающие поля берутся по умолчанию.

## [0.5.0] — 2026-11-08

Новые файлы «с нуля», режимы имён результатов и точный размер PNG.

### Добавлено

- **Создание файлов «с нуля»** (`pumper::generate`, команда `generate`/`make`):
  `file-pumper-cli generate [--size <МБ[,МБ]>] [--type bin|png|gif|jpg|webp]
  [--name ОСНОВА] [--count N] [--payload <файл> ...] [--out-dir ПАПКА] [--dry-run]
  [--verify] [--report ФАЙЛ]`. Внутри всегда криптослучайные байты (`getrandom`), поэтому
  `zip`, `gzip` и `7z` файл не уменьшают; картиночные типы остаются валидными
  (маленькое изображение + объём внутри структуры: чанки PNG, комментарий GIF).
  Списки размеров работают так же, как в `pump`: каждый размер из `--size`
  повторяется `--count` раз (`--size 5,10 --count 2` — четыре файла), плюс режимы
  имён (`--names`) и отчёты.
- **Второе дно при генерации:** `--payload` (можно несколько — тогда ZIP-бандл)
  прячется в созданный файл, но размер остаётся ровно целевым: длина контейнера
  считается заранее, а служебные байты формата измеряются на минимальном носителе
  (`batch::generate_one`, `payload::prepare_payload`,
  `PreparedPayload::container_len`).
- **Интерфейс:** раздел «5. Создать файл с нуля» — тип файла, основа имени, число
  файлов и галочка «Прицепить второе дно» (нагрузка из пункта 4); прогресс,
  отмена и окно результата как у накачки.
- Тесты: `tests/cli_generate.rs` (11 тестов) и unit-тесты `pumper::generate`,
  `batch` (план генерации, точный размер, генерация с нагрузкой и без).
- **Режимы имён результатов** (`batch::NameMode`): флаг `--names size|plain|random` и
  кнопки в окне. `plain` убирает пометку размера (`photo_10MB.png` → `photo.png`),
  `random` даёт нейтральное имя из двух слов и числа (`quiet-river-4821.png`).
  Работает для пакетной накачки (`--out-dir`, `--from-dir`), для пакетного `embed`
  и для списка файлов в интерфейсе; режим запоминается в настройках.
- **Интерфейс:** кнопка «Убрать размер из имени» / «Вернуть размер в имя», галочка
  «Случайное имя файла» и строка с примером имени результата.
- Тесты: `tests/cli_names.rs` (6 тестов) и unit-тесты `batch` (разбор режима,
  `plain`/`random`, имя рядом с исходником, план с режимом имён).
- **README:** раздел «Где файл переживёт загрузку» — какими выходят файлы
  (сигнатуры, где лежит паддинг: внутри структуры PNG/GIF или хвостом за
  `EOI`/RIFF), что видит загрузчик и что убивает встроенное (пережатие, лимиты
  размера, строгие валидаторы).

### Исправлено

- **PNG-паддинг учитывает служебные байты чанков** (`pumper::padding`): раньше
  каждый чанк добавлял 12 байт сверх цели, и файл выходил больше запрошенного
  размера на `12 × число чанков` (касалось `png-chunks`, `upscale`, `animation`
  с `--format png` и генерации PNG). Тест `pumper::padding` проверяет точный
  размер и на нескольких чанках.

## [0.4.0] — 2026-11-08

Управляемый пакет: план до запуска, папки и списки файлов, свои размеры,
параллельная обработка, отчёты, несколько нагрузок в одном носителе и `verify`.

### Добавлено

- **Пакетный `embed`:** `file-pumper-cli embed <носитель>... --payload <файл>
  [--payload ...] [--out-dir ПАПКА] [--output ФАЙЛ]`. Старый синтаксис
  `embed <носитель> <нагрузка> [выход]` сохранён.
- **Бандл из нескольких нагрузок:** повторный `--payload` упаковывает файлы в ZIP
  внутри контейнера (новый флаг `FLAG_BUNDLE`). `extract` распаковывает бандл по
  файлам, `inspect` печатает оглавление, `verify` проверяет его целостность.
- **Команда `verify <носитель>...`:** перечитывает носитель, проверяет SHA-256 и
  печатает имя/размер/число копий; код выхода `1` при повреждении или отсутствии
  нагрузки.
- **Режимы размера:** `--size-mode exact|at-least|add` и список размеров
  `--size 5,10,2` — по размеру на каждый файл (`batch::TargetMode`, `PumpPlan`).
- **Сбор входов:** `--from-dir ПАПКА [--recursive] [--ext png,jpg]`, `--from-file
  СПИСОК` (комментарии `#`, относительные пути от файла списка), дедупликация
  (`src/scan.rs`).
- **`--dry-run`** для `pump` и `embed`: печатает план и не создаёт ни файлов, ни
  папок.
- **`--jobs N`:** параллельный пакет до 16 потоков с монотонным общим прогрессом и
  отчётом в исходном порядке (`batch::pump_parallel`).
- **`--report`:** CSV (`input,output,status,bytes,message`) или JSON, формат по
  расширению (`src/report.rs`).
- **`--skip-unsupported`:** предпроверка метода до запуска
  (`batch::support_error`), такие файлы попадают в отчёт как `skipped`, а не
  `failed`.
- **Предупреждения о размерах:** больше 2 ГБ, больше 4 ГБ/FAT32, ограничения PNG
  (`scan::limits_warnings`).
- **Интерфейс:** списки носителей и нагрузок с удалением строк, режим размера,
  drag & drop папок (рекурсивно), сохранение настроек между запусками
  (`eframe` persistence + `serde`, пароль не сохраняется), распаковка бандла в
  выбранную папку.
- **Резервирование имён** (`util::Reservations`): одинаковые имена из разных папок
  больше не конфликтуют даже при параллельной записи.
- Тесты: `tests/cli_extras.rs` (13 тестов) и unit-тесты `scan`, `report`, `bundle`,
  `batch` (режимы размера, план, параллельный прогон).

### Изменено

- `BatchItem` теперь хранит целевой размер (`target`), поэтому у файлов одного
  пакета размеры могут различаться; `pump` больше не принимает один размер на всех.
- `ItemResult::Skipped` несёт причину пропуска (`Skipped { reason }`).
- Папки результатов создаются во время записи, а не на этапе плана — ради
  честного `--dry-run`.
- `ContainerOptions` получил поле `bundle`, `PayloadInfo`/`HeaderInfo` — флаг
  `bundle`; старые контейнеры читаются без изменений.
- Версия `0.4.0`; обновлены README, CHANGELOG и `scripts/release_checksums.py`.

## [0.3.0] — 2026-11-08

Пакетная накачка: сразу несколько файлов за один запуск — в окне и в терминале.

### Добавлено

- **Пакетный `pump`:** `file-pumper-cli pump <вход>... --size <МБ> [--out-dir ПАПКА]
  [--output ФАЙЛ]`. Файлы обрабатываются по очереди, ошибка одного не прерывает
  остальные; в конце печатается «Готово: …» по каждому файлу и сводка, код выхода
  `1`, если хоть один файл не удался.
- **`extract` и `inspect` принимают несколько носителей**; `extract --out-dir`
  складывает извлечённые файлы в указанную папку.
- **Имена результатов** — `<имя>_<размер>MB.<расширение>` (например,
  `photo_10MB.png`). Существующие файлы не перезаписываются: при совпадении
  добавляется суффикс `-2`, `-3` (`util::unique_path`).
- **Интерфейс:** мультивыбор файлов, список пакета с состоянием каждой строки
  (ожидает / обработка / готово с размером / ошибка), удаление строк кнопкой «✕»,
  «Очистить», выбор папки результатов, общий прогресс «Файл 3 из 8» и сводный
  диалог после пакета со списком ошибок.
- **Drag & drop** добавляет в пакет все перетащенные файлы, а не только первый.
- Новый модуль `src/batch.rs` (`BatchItem`, `BatchReport`, `pump`, `pump_one`,
  `output_path`) и `util::Job::child` — дочерний контекст с общим флагом отмены.
- Тесты: `tests/cli_batch.rs` (пакет, коды выхода, устаревший синтаксис,
  коллизии имён, несколько носителей) и unit-тесты в `batch.rs`.

### Изменено

- Второй позиционный аргумент `pump` и `extract` больше не считается выходным
  файлом: для точного имени результата используйте `--output`. Старый синтаксис
  `pump <вход> <выход>` продолжает работать, но печатает предупреждение.
- `pump` печатает строку результата по каждому файлу в stdout
  (`Готово: <вход> -> <выход> (N МБ)`), ошибки по файлам — в stderr.

## [0.2.0] — 2026-11-07

Первый публичный релиз. Приложение разделено на две сборки и получило
кроссплатформенные артефакты.

### Добавлено

- **Два бинарника:** `file-pumper` (окно, на Windows подсистема GUI —
  консоль не открывается) и `file-pumper-cli` (`pump`, `embed`, `extract`,
  `inspect`).
- **Накачка до размера** шестью методами: `animation` (GIF), `png-chunks`,
  `upscale`, `svg`, `office` (ZIP/Office/PDF), `padding`.
- **Полезная нагрузка** в PNG (`ufPl`), JPEG (APP15), GIF (comment), WebP (`UFP1`),
  SVG (`metadata`) и в хвост любого файла (маркер `LFPU`).
- **Контейнер версии 2:** флаги, SHA-256 блоба, CRC32 заголовка, концевой маркер с
  длиной; версия 1 продолжает читаться.
- **Сжатие** `deflate` и **шифрование паролем**: Argon2id (19 МиБ, 2 прохода) →
  ChaCha20-Poly1305 с проверкой границ параметров KDF.
- **1–3 копии нагрузки** в разных чанках/сегментах — извлечение выживает при
  обрезании хвоста файла сервером.
- **Проверка после записи:** повторное чтение файла, сверка контрольных сумм и
  пробное декодирование изображения.
- **Интерфейс:** drag & drop файлов, превью перед извлечением с запросом пароля,
  прогресс, отмена, показ результата в проводнике, масштабируемое окно с прокруткой.
- **Кроссплатформенные сборки:** Windows x64 и Linux x86_64 (кросс-компиляция
  `cargo-zigbuild`, минимальная glibc 2.17); архивы опубликованы в релизе
  [`v0.2.0`](https://github.com/Xvicd/FilePumper/releases/tag/v0.2.0) с контрольными
  суммами SHA-256.
- `scripts/check_linux_build.sh` — проверка Linux-бинарника (версия, круговой прогон,
  `ldd`), CI и workflow релиза, `scripts/release_checksums.py` — проверка файлов
  релиза и обновление их SHA-256 в описании.

### Исправлено

- Графическая сборка на Windows больше не открывает окно консоли рядом с окном
  приложения.
